Payment-to-invoice reconciliation: given an invoice ledger and a bank statement,
work out which invoices each payment paid, conserve money to the cent, and send
anything uncertain to a human instead of guessing.

## Two distributions

- **`settle-engine`** — the engine, a Typer CLI, and `POST /reconcile`. No database, no UI, no web dependencies.
- **`settle-app`** — a server-rendered browser interface with sign-in, run history, column mapping for real accounting exports, and a Docker/Caddy deployment.

The engine does not know the app exists, and a test enforces it.

## Install

```bash
pip install git+https://github.com/nagytamasgit/settle.git
```

Or take `settle_engine-0.1.0-py3-none-any.whl` from the assets below. The
distribution is not on PyPI, so there is no `pip install settle-engine`.

## Measured

400 invoices per run, 5 seeds per row, noise rising on all four dimensions at once:

| noise | precision | recall | sent to review |
|---:|---:|---:|---:|
| 0.0 | 100.0% | 100.0% | 0.0% |
| 0.2 | 99.4% | 92.8% | 4.1% |
| 0.5 | 97.1% | 70.2% | 19.7% |

Precision barely moves; recall carries the cost. That is the design — uncertainty
becomes human work rather than wrong allocations. CI re-runs the benchmark and
fails if the committed numbers stop reproducing.

436 tests, 94.35% coverage, ruff and strict mypy clean.
